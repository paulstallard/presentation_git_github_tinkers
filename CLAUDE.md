# Presentation brief: Git and GitHub

## Audience and occasion
- Tinkers Study Group, a local computer club, on 4 November 2026.
- Most members are retired. Many have coded in the past and a few still do.
- Some have used public projects on GitHub, but very few use git themselves.

## Goals
- Help people understand the **terminology** (repository, commit, branch, merge, clone, push, pull, fork, pull request, and so on).
- Explain **why** people use version control.
- Make the **difference between git and GitHub** clear, since it is widely misunderstood.

## Constraints
- About 20 minutes, so keep it short.
- Keep it to an introduction. A later meeting may go into more detail for those interested, so leave the deeper material (hands-on commands, workflows, branching strategies) for that session.
- The group is very interactive, with lots of questions and discussion, so keep the slide count low.
- The meeting organiser introduces the talk and handles any follow-up meeting, so the talk itself doesn't mention it.
- The live demo opens one project (Pi-hole) and walks around it from the main page, rather than using separate links to each GitHub page.
